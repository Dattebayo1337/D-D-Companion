# D&D Companion · Кампании и справочники

Локальное русскоязычное приложение для игроков и мастеров D&D. Реализованы основа платформы, система персонажей этапа 3 и справочники: библиотека заклинаний и существ, классы, подклассы, расы/виды, предыстории, черты, оружие, доспехи, снаряжение, магические предметы, состояния и правила. **Это ещё не реализация всех шести этапов.** Доступны создание и лист персонажа, повышение уровня и мультикласс, инвентарь, книга заклинаний, ресурсы и отдых. Добавлены кампании, NPC, задания, локации, журнал сессий, сохранённые бои и трекер инициативы, экран мастера и кубы. Возможности и ограничения описаны в [PHASE4.md](docs/PHASE4.md).

## Быстрый запуск

Запуск в контейнере и настройка GitHub Actions: [Docker и CI](docs/DOCKER_CI.md).

Требования: **Node.js 24+**, pnpm 11.19+, современный браузер. Windows, macOS или Linux. Для установки пакетов нужен интернет; после установки локальный сервер не обращается к внешним сервисам.

```sh
pnpm install
```

Скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env` в PowerShell, `cp .env.example .env` в bash), затем:

```sh
pnpm db:generate
pnpm db:migrate
pnpm data:srd
pnpm build
pnpm start
```

Открыть http://127.0.0.1:3000. `data:srd` загружает **2519 записей SRD**: 658 заклинаний, 647 существ и 1214 статей справочников, с русскими текстами OmnisGM и разделением редакций 2014/2024. Повторный импорт не создаёт дубликаты. `pnpm data:demo` — необязательный отдельный набор из 7 учебных Homebrew-записей; существующий демонстрационный контент сохраняется. SRD — открытая часть правил, а не все заклинания из всех опубликованных книг.

В переданном рабочем каталоге зависимости уже установлены, SQLite проинициализирована и production-сборка создана. Для повторного запуска достаточно `pnpm start` либо `node node_modules/next/dist/bin/next start --hostname 127.0.0.1`. Сервер привязан только к loopback. Не публикуйте его в сети без добавления аутентификации и разграничения доступа.

## Разработка и проверки

```sh
pnpm dev
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

`test` запускает Node Test Runner с TypeScript loader, изолированной временной SQLite и настоящей SQL-миграцией. Рабочая БД не затрагивается. Loader транспилирует TS для запуска, отдельный `typecheck` выполняет строгую проверку. Путь временной БД находится в системном temp; его можно удалить после тестов. Набор проверяет поиск, локализацию, фильтры, идемпотентность, FK, ревизии, защиту официального контента, ошибки импорта и rollback.

Для среды Windows с ограничением Node `spawn` сборка использует `useTypeScriptCli: false`, `webpackBuildWorker: false`, `workerThreads: true`; проверки TypeScript не отключены. `dev` обычно запускает дочерний процесс; при ограничении среды используйте production-команды выше. В обычном терминале Prisma CLI работает стандартно. Подробности проверки текущего окружения — `docs/VERIFICATION.md`.

## Справочники этапа 2

Открываются через меню «Справочник» и карточку на главной. Общий поиск охватывает все типы записей; совпадение названия имеет приоритет. Классы показывают таблицы уровней 1–20, подклассы связаны с классами. Все карточки содержат русские правила, таблицы и источник. Подробная матрица покрытия: `docs/PHASE2.md`.

## Данные SRD

Готовые пакеты: `data/srd/{spells,monsters,references}-{2014,2024}.json`. Их можно импортировать через менеджер данных или `pnpm data:srd`. Для воспроизводимой сборки из локальных исходников: `pnpm data:srd:build` (заклинания), `pnpm data:monsters:build`, `pnpm data:references:build`. Интернет для этих команд не требуется.

Списки не загружают все stat blocks в браузер.

## База и миграции

По умолчанию `DATABASE_URL="file:./companion.db"`, файл относительно `prisma/schema.prisma`: `prisma/companion.db`. Миграции применяются `pnpm db:migrate`; новые в разработке создаются `pnpm exec prisma migrate dev --name <name>`. Не редактируйте применённые миграции.

Для PostgreSQL создайте отдельную БД, измените `.env`:

```dotenv
DATABASE_URL="postgresql://USER:PASSWORD@127.0.0.1:5432/companion"
DATABASE_PROVIDER="postgresql"
```

```sh
pnpm db:postgres:generate
pnpm db:postgres:migrate
pnpm build
pnpm start
```

Расширение `pg_trgm` должно быть доступно роли миграции. Схемы двух провайдеров синхронны по предметным моделям; SQL-истории разные. Генерация другого клиента требует перезапуска сервера. Нельзя перенести SQLite простым изменением URL: экспортируйте JSON, создайте новую БД и импортируйте туда. Снимки ContentRevision через JSON не переносятся; для полной истории используйте резервную копию самой БД.

SQLite-поиск перебирает компактные поисковые документы на сервере, затем загружает страницу сущностей. Для больших каталогов предусмотрен PostgreSQL FTS + pg_trgm. PostgreSQL-адаптер и SQL включены, но live PostgreSQL в этом окружении не запускался; требуется отдельный интеграционный прогон перед его использованием в production.

## Импорт, SRD и Homebrew

В браузере откройте «Менеджер данных», выберите JSON и нажмите «Проверить набор» или «Импортировать». Импорт повторяет все обязательные проверки; предварительная проверка не является разрешением обойти их.

```sh
pnpm data:validate data/examples/homebrew.json
pnpm data:import data/examples/homebrew.json
pnpm validate:ru
```

Формат описан в `docs/IMPORT_FORMAT.md`, исполняемая спецификация — `src/entities/content.ts`. Текущий адаптер принимает нормализованный JSON, а не PDF книг и не произвольную структуру внешнего SRD. Для нового провайдера требуется parser adapter, сохраняющий канонические механические значения. Перевод готовится до импорта, в runtime переводчика нет.

Включены русско-английские наборы заклинаний SRD 5.1 и 5.2.1 с лицензиями и атрибуцией; см. docs/SRD_DATA.md. Для дополнительных наборов обязательны точная лицензия, атрибуция, source/rulesVersion и русский перевод. Не используйте демонстрационный набор как официальные правила. Ни авторизация сайтов, ни DRM, ни paywall не обходятся.

Домашний контент можно подготовить как JSON с `contentOrigin: "Homebrew"`. Для правки встроенной записи скопируйте её с новым UUID и происхождением Homebrew; официальный оригинал защищён от изменения. Редактор Clone → Edit доступен в «Авторском контенте» и внутри карточек; см. [PHASE5.md](docs/PHASE5.md).

## Локализация

Русские nameRu/descriptionRu не подменяются английскими. `Approved` с ошибками локализации импортировать нельзя. Другие статусы допускают рабочие черновики, которые видит проверка менеджера, но не обычный справочник. Команда `pnpm validate:ru` реализует Validate Russian Localization и завершается ненулевым кодом при замечаниях. Проверка латиницы — консервативная эвристика, а не доказательство качества перевода: редактор отвечает за точность механики.

В словаре один основной перевод на `(original, category, edition)`. Aliases расширяют поиск. Новые неизвестные enum отвергаются Zod; при расширении списка TypeScript требует дополнить словари русского UI.

## Экспорт и резервное копирование

«Экспорт набора» скачивает текущий Dataset. Его можно импортировать в новую БД. Это **не полный backup**: история ревизий и локальные настройки браузера в набор не входят.

Полная локальная резервная копия: остановите сервер, скопируйте `prisma/companion.db` в безопасное место; если есть файлы `-wal`/`-shm`, выполняйте backup средствами SQLite либо корректно завершите все соединения перед копированием. Восстановление — при остановленном сервере заменить файл БД резервной копией той же версии и применить новые миграции. Настройки браузера хранятся отдельно под ключом `companion-settings`. Универсальный backup всех будущих сущностей — отдельный этап.

## API

GET `/api/content`, `/api/spells`, `/api/monsters`; query: `q`, `edition`, `kind`, `level`, `school`, `ritual`, `concentration`, `type`, `size`, `cr`, `sourceBookId`, `damageType`, `page`, `pageSize` (максимум 100). GET `/api/content/:uuid`, `/api/sources`, `/api/editions`, `/api/overview`.

GET `/api/manager` — аудит; GET `/api/manager?action=export` — Dataset. POST `/api/manager?action=validate|import` с JSON-набором; POST `/api/manager?action=reindex`. Ошибки возвращаются по-русски. API пока предназначен только для доверенного локального пользователя.

## Лицензии

Разделение кода, SRD, лицензированных, импортированных и авторских материалов — `THIRD_PARTY_LICENSES.md`.

Редакция выбирается кнопками **2014 / 2024** в верхней панели и сохраняется локально. В каталогах и поиске отображается одна редакция за раз; введённый поисковый запрос остаётся при переключении. При первом запуске выбрана 2024.

## Персонажи — этап 3

Раздел «Персонажи» использует общий переключатель редакций. Создание проходит в шесть шагов; данные сохраняются в SQLite, обновления защищены номером версии от потери параллельных изменений. Карточки справочника закрываются нажатием снаружи, Escape и кнопкой ×.

Подробный состав автоматических расчётов и ручных выборов: [PHASE3.md](docs/PHASE3.md). Обновление существующей установки: `pnpm db:generate`, `pnpm db:migrate`, `pnpm build`. Экспорт библиотеки не содержит персонажей; используйте экспорт JSON из листа либо резервную копию SQLite при остановленном сервере.

## Подклассы по классам

Вкладка «Подклассы» сначала предлагает 12 классов выбранной редакции, затем показывает только подклассы выбранного класса. Есть поиск классов, поиск внутри подклассов, фильтр источника и возврат с сохранением поиска класса. Смена редакции возвращает к выбору класса.

Состав обеих «Книг игрока» дополнен до 40 подклассов 2014 и 48 подклассов 2024. Добавлены 28 и 36 самостоятельных кратких обзоров с уровнями развития и ссылками на страницы классов ДнД.су; полные записи SRD сохранены. Это полный перечень PHB, а не всех дополнительных книг. Обзоры не заменяют полные правила и не добавляют автоматизацию особенностей подклассов.

Импорт включён в `pnpm data:srd`. Для существующей базы: `pnpm data:subclasses`; пересборка пакетов: `pnpm data:subclasses:build`.
