# Этап 3 — система персонажей

## Возможности

- Мастер из шести шагов: происхождение, характеристики, владения, снаряжение, заклинания, проверка. 12 классов каждой редакции, виды/расы, предыстории и подклассы из установленного SRD.
- Стандартный набор, покупка за 27 очков, ручные значения и серверные броски 4d6 с отбрасыванием меньшего кубика. Бонусы характеристик хранятся отдельно.
- Лист: характеристики, модификаторы, бонус мастерства, спасброски, навыки и компетентность, пассивная Внимательность, хиты, временные хиты, базовый КД, инициатива и скорость.
- Урон сначала расходует временные хиты, лечение ограничено максимумом. При нуле хитов концентрация прекращается. Состояния, истощение и спасброски от смерти отмечаются вручную.
- Повышение до 20 общего уровня со средним приростом хитов; мультикласс с проверкой требований характеристик. API также принимает введённый бросок хитов. Телосложение пересчитывает максимум ретроактивно. Новый класс не даёт максимальную кость повторно.
- Подклассы с проверкой родительского класса и минимального уровня, список полученных умений и полный текст правил; выбор черт.
- Инвентарь: количество, надетые предметы, настройка (до трёх), монеты. Базовые доспехи и щит участвуют в КД. Карточка предмета открывается по названию.
- Книга заклинаний по классу и доступному кругу: известные/записанные, подготовленные, всегда доступные. Применение расходует выбранную ячейку, заговор не расходует её. Ячейки договора учитываются отдельно. Отслеживается одно заклинание концентрации; текст заклинания открывается из листа.
- Основные ограниченные ресурсы классов и короткий/длительный отдых. В 2014 длительный отдых возвращает половину костей хитов с округлением вниз (минимум одну), в 2024 — все. При мультиклассе сначала возвращаются большие кости. Расход кости хитов использует серверный бросок.
- Локальное сохранение, архив/восстановление, экспорт JSON листа. Изменения из устаревшего окна отклоняются HTTP 409. Числовые поправки в листе сохраняются при выходе из поля.

## Границы автоматизации

Это система листа и базовых правил, а не полный Effect System этапа 6. Выбор владений, языков, бонусов происхождения, повышения характеристик, черт, подготовка и допустимое количество заклинаний сверяются с текстом правил. Исключения от черт и подклассов не выводятся автоматически. «Всегда доступно» позволяет учитывать такие исключения вручную.

Эффекты заклинаний, магических предметов, подклассов, условий и истощения не применяются к числам автоматически. Специальное восстановление ресурсов (например, магическое восстановление), неограниченные способности и особые ресурсы подклассов проверяются по тексту умения. КД имеет ручную замену, максимум хитов и инициатива — поправки; скорость задаётся вручную. Владения доспехами, грузоподъёмность, оружейные атаки, преимущества/помехи и проверки концентрации не автоматизированы. Длительный отдых выполняется по нажатию после проверки условий игроком, без таймера игрового времени.

Экспорт JSON сохраняет полный лист, но отдельный мастер обратного импорта персонажа пока не добавлен. Для полной резервной копии используйте файл SQLite при остановленном сервере. Менеджер данных экспортирует справочники, отдельно от персонажей.

## Архитектура

- `entities/character.ts`: строгий контракт Zod.
- `domain/rules/character.ts`: чистые расчёты, мультикласс, валидация, отдых и повышение уровня.
- `data/rules/character-rules.json`: таблицы 24 классов и 26 доспехов из проверенного SRD. Пересборка: `pnpm data:characters:build`.
- `services/characters/service.ts`: команды, проверка связей с редакцией и конкурентная запись по версии.
- `api/characters`: каталог и список через GET, изменения через POST с проверкой Origin и JSON.
- `features/characters`: адаптивный мастер и лист; общая карточка `Detail`.
- Миграция `0003_characters` для SQLite и PostgreSQL. Проверено на SQLite; PostgreSQL-сервер в этой среде не запускался.

Закрытие `Detail`: нажатие начинается и заканчивается за границами диалога. Внутренние нажатия и перетаскивание из карточки наружу не закрывают её. Escape и кнопка закрытия сохранены.
