# Этап 5 — авторская мастерская и коллекции

Версия 0.5.0 добавляет редакторы, Clone → Edit, локальные коллекции и перенос авторских материалов. Следующий основной этап — сравнение редакций и расширенный движок эффектов.

## Мастерская

Откройте «Авторский контент». Переключатель 2014 / 2024 определяет редакцию новой карточки и списка. Поддерживаются заклинания, существа и все 11 категорий справочника. Формы редактируют основные тексты, параметры, свойства, умения и уровни развития. Связь подкласса с классом обязательна; источник и редакция существующей записи не меняются.

«Копия из справочника» и «Создать авторскую копию» внутри карточки создают новый UUID с происхождением Homebrew. Исходник остаётся неизменным. Условия исходного материала сохраняются в поле лицензии; создание копии само по себе не даёт новых прав на распространение.

«Сохранить черновик» записывает карточку в SQLite с HumanReviewed: её видно в мастерской, но нет в общих каталогах. «Опубликовать» проверяет обязательные русские поля и сохраняет Approved. Для снятия публикации сохраните карточку как черновик. Предпросмотр использует обычную карточку с иконкой и кратким описанием.

Каждое сохранение повышает contentVersion и создаёт ContentRevision. Конфликт версий не перезаписывает чужие изменения. Незавершённый редактор сохраняет один локальный черновик на редакцию; его можно вернуть отдельной кнопкой или скачать как JSON карточки. Новая правка заменяет предыдущий локальный черновик. Скачанный одиночный черновик — резервная копия для ручной работы, а не готовый Dataset для импорта.

Новые классы и особенности не получают произвольную программную автоматизацию. Правила применяются вручную в пределах возможностей существующего движка. Код из описаний и пакетов не исполняется.

## JSON, CSV и .dndpack

Вкладка «Пакеты» экспортирует авторские карточки обеих редакций, включая черновики, с их источниками. Можно указать название, автора, версию и описание манифеста. JSON — существующий нормализованный Dataset. CSV содержит колонки `type,json`: строки meta, sources, entries, terms, relations; JSON в ячейке сохраняет вложенные механики без потери структуры. Обычная произвольная таблица CSV не поддерживается.

`.dndpack` — стандартный ZIP: `manifest.json`, `data/dataset.json`, пустой `assets/`. Читаются сохранённые и Deflate-записи. Проверяются размеры, пути, дубли, CRC, манифест, редакции и зависимости. Вложенные изображения и другие файлы пока не поддерживаются и отвергаются. Файл интерфейса ограничен 22 МБ; распакованные данные — 32 МБ. ZIP64, шифрование и многотомные архивы не поддерживаются.

Зависимости — UUID внешних классов, на которые ссылаются подклассы. Их нужно установить до пакета. Мастерская принимает только Homebrew-карточки и источники, без изменения терминологии и ContentRelation. Другие наборы импортируются менеджером данных. Проверка не меняет базу; импорт повторяет проверки и применяет пакет атомарно. Повтор одинакового пакета пропускает существующие записи. Старые или несовместимые версии отклоняются. Установленного реестра пакетов и их удаления целиком пока нет; данные становятся обычными записями библиотеки.

## Коллекции

Создавайте подборки карточек обеих редакций: поиск, добавление без дублей, удаление ссылки из подборки, изменение порядка, название и описание, архив/восстановление. Удаление ссылки не удаляет карточку. Коллекция вмещает до 1000 ссылок и сохраняется в SQLite с контролем версии. Снятая с публикации карточка остаётся ссылкой в коллекции, которую можно убрать отдельно. Экспорт списка содержит UUID, название и описание, без самих карточек; импорт коллекций пока не реализован. NPC кампаний пока не входят в подборки справочника.

Миграция `0006_collections` добавляет Collection. Обновление: `pnpm db:generate`, `pnpm db:migrate`, `pnpm build`, перезапуск. PostgreSQL-схема и SQL подготовлены, живой PostgreSQL не проверялся. Полный перенос коллекций требует резервной копии SQLite; экспорт библиотеки и .dndpack их не включают.

## Оформление и полнота данных

Тёмная тема заменена на графитовую с медными акцентами, контрастными полями, отдельными цветами предупреждений, активных вкладок и карточек. Настройка сохраняется в браузере; светлая тема остаётся доступной.

«Менеджер данных → Полнота справочников» показывает датированный снимок сверки с ДнД.су и выгрузку кандидатов со ссылками. [DNDSU_COVERAGE.md](DNDSU_COVERAGE.md) описывает метод и ограничения. Это проверка наполнения, не импорт всех текстов сайта. Сравнение не объявляет карточку полной лишь по совпадению названия.

## API

- GET `/api/workshop?edition=5e_2024` — авторские записи, включая черновики.
- POST `/api/workshop` — `{entry, expectedVersion}`; 0 для создания.
- GET/POST `/api/workshop?mode=collections` — коллекции и `{id?, version, data}`.
- POST `/api/workshop/packages` — action export/validate/import, format json/csv/dndpack. Для ZIP payload передаётся как base64. Экспорт допускает фильтр ids.
- GET `/api/coverage` — краткий отчёт; `?download=1` — полный JSON.

API рассчитан на доверенного локального пользователя, с проверкой origin для записи. Облачная авторизация не добавлялась.
